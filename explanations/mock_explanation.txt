# Screen 3 — Mock Exam Session

First new major screen.

This is the equivalent of:

```text
PracticeScreen
```

but with:

### Additional requirements

#### Timer

Top card contains:

```text

22:32

Questions

```

---

### Color State

#### Green

More than 10 minutes remaining.

#### Amber

5–10 minutes remaining.

#### Red

Less than 5 minutes remaining.

Exactly as shown in screenshots.

---

### Actions

Bottom contains:

```text
Flag
Review
Next
```

---

### Flag Button

Marks question for review.

Stored in session.

```dart
Set<int> flaggedQuestions
```

---

### Review Button

User can temporarily review answers before submission.

Opens:

```text
Mock Review Screen
```

without ending test.

---

### Next Button

Moves to next question.

---

### Important Difference from Practice

Practice:

```text
Answer
↓
Show explanation immediately
```

Mock:

```text
Answer
↓
NO explanation
↓
Next
```

This is critical.

Real exams do not reveal answers during test.

# Biggest Architectural Revelation

The mock feature should NOT have its own review implementation.

Reuse:

```text
practice/presentation/screens/review_screen.dart

practice/presentation/screens/review_question_detail_screen.dart
```

because:

* identical UI
* identical logic
* identical filters
* identical navigation

This keeps maintenance low.

# Recommended Session Model

Create:

```dart
class MockSessionController {
  List<QuestionModel> questions;

  Map<int, String> answers;

  Set<int> flagged;

  int currentIndex;

  Duration remainingTime;

  bool submitted;
}
```

This mirrors the production-grade structure we introduced for Practice and gives Mock a completely independent state lifecycle.

The biggest win is that roughly **60–70% of the review and question-detail infrastructure is already built in Practice and should be shared instead of duplicated**, while Mock-specific work focuses mainly on **timer management, submission flow, pass/fail calculation, and result reporting**.
